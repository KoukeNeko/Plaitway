## Changes

0.10.2, 0.10.3 and 0.10.4 were tagged but not published, as notarization of the macOS app failed. This release includes their changes, listed here against 0.10.1.

- Linux: the menu of the GNOME Shell extension shows the state of each profile beside its switch: a spinner while the profile connects, reconnects or disconnects, a check mark when it is connected, a cross when it has failed, a key when it awaits credentials, and a dim dot when it is not connected
- Linux: the extension's menu stays open when a switch is pressed, so that several profiles can be switched at once, and a switch whose command has not answered yet is no longer moved back by the next poll
- Linux: a profile that requires credentials can be connected from the extension's menu. The app answers the credential request with the password saved in the keyring, or opens its window and asks for it. Previously the profile was stopped as soon as it requested credentials, and its switch returned to off
- Linux: while the extension is loaded in the running Shell, the app does not show its own tray item, so that only one icon represents Plaitway in the top bar. This also holds when the app starts before the Shell has loaded the extension, as it can at login. The tray item is shown again when the extension is disabled, and stays where the Shell cannot be queried
- Linux: while the extension is loaded, closing the window hides it and the app keeps running in the background, so that it can answer credential requests; the extension's menu opens the window again
- Packaging: when Apple's notary service refuses the credentials, the release build now reports the reason Apple gives

The macOS app, the Windows app and the helper are the same as in 0.10.1.
